# Логин через GitHub

Соображения, не реализация.

## Коротко

Да, если фабрика будет жить на сервере или ею будут пользоваться несколько человек. Если она
остаётся локальным инструментом для одного человека, это не первоочередная задача: сначала
пункты 1–4 из текущего списка.

## Почему он здесь хорошо ложится

- **Схема для этого уже готова.** В `transitions.actor` и `human_requests.answered_by` есть
  поля под автора, но сейчас там всегда `"user"` (`engine.py:124`). С логином появится
  настоящий журнал: кто одобрил план, кто ответил в inbox, кто нажал Open PR.
- **Права можно брать прямо из GitHub.** Перед действием в проекте проверять право
  пользователя на `project.repo` (write или maintain) и не вести собственную таблицу ролей.
  Это естественно для инструмента, который и так работает с GitHub.
- **GitHub App уже есть** (`github_app_id`). У App есть user-to-server OAuth, поэтому
  отдельное OAuth-приложение не нужно.
- **HttpOnly-cookie вместо токена в localStorage** закрывает пункт 5. SSE уже идёт через
  `fetch`, так что cookie будут отправляться без переделок.

## Что учесть

- **Bearer-токен остаётся** для MCP-сервера и автоматизации как сервисный токен. Режим
  «только токен» стоит сохранить для локального запуска.
- **CSRF.** С cookie он появляется: нужен `SameSite=Lax` и проверка `Origin` на изменяющих
  запросах.
- **Allowlist.** Нужен список разрешённых пользователей или организации, иначе войти сможет
  любой аккаунт GitHub.
- **Callback URL** требует фиксированного адреса. Для localhost это работает, для удалённого
  хоста понадобится домен.
